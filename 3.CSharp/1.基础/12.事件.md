# 事件

## 事件（Event）

C# 事件（Event）是一种类成员，用于将特定通知发送给订阅者。事件基于委托实现观察者模式，让对象将状态变化通知其他对象，而不需要知道这些对象的细节。

> **简单理解**：`delegate` 定义了"函数签名"（能注册什么样的方法），`event` 则是对 delegate 的封装，限制了外部只能 `+=`/`-=`，不能直接赋值或清空。

## 基础示例（自定义委托方式）

```csharp
// 1. 声明委托类型（定义事件处理方法的签名）
public delegate void HealthChangedHandler(int oldHealth, int newHealth);

// 2. 发布器（Publisher）
public class Player
{
    public string Name { get; }
    private int _health = 100;

    // 3. 声明事件
    public event HealthChangedHandler OnHealthChanged;

    public Player(string name) => Name = name;

    public void TakeDamage(int damage)
    {
        int oldHealth = _health;
        _health -= damage;

        // 4. 触发事件（?.Invoke 避免 null 引用）
        OnHealthChanged?.Invoke(oldHealth, _health);
    }
}

// 5. 订阅器（Subscriber）
public class UI
{
    public void Subscribe(Player player)
    {
        // 订阅事件
        player.OnHealthChanged += OnPlayerHealthChanged;
    }

    private void OnPlayerHealthChanged(int oldHp, int newHp)
    {
        Console.WriteLine($"血量变化: {oldHp} → {newHp}");
    }

    public void Unsubscribe(Player player)
    {
        // 取消订阅（防止内存泄漏！）
        player.OnHealthChanged -= OnPlayerHealthChanged;
    }
}

// 使用
var player = new Player("Hero");
var ui = new UI();
ui.Subscribe(player);
player.TakeDamage(30);  // 输出: 血量变化: 100 → 70
```

## 标准事件模式（EventHandler\<T\>）

.NET 推荐使用 `EventHandler<TEventArgs>` 而非自定义委托，这是框架约定的标准模式：

```csharp
// 自定义事件参数（继承 EventArgs）
public class HealthChangedEventArgs : EventArgs
{
    public int OldHealth { get; }
    public int NewHealth { get; }
    public HealthChangedEventArgs(int oldHp, int newHp)
    {
        OldHealth = oldHp;
        NewHealth = newHp;
    }
}

public class Player
{
    private int _health = 100;

    // 使用 EventHandler<T> —— 标准模式
    public event EventHandler<HealthChangedEventArgs> OnHealthChanged;

    public void TakeDamage(int damage)
    {
        int old = _health;
        _health -= damage;
        OnHealthChanged?.Invoke(this, new HealthChangedEventArgs(old, _health));
    }
}

// 订阅
var player = new Player();
player.OnHealthChanged += (sender, e) =>
{
    Console.WriteLine($"{(sender as Player)?.GetType().Name} 血量: {e.OldHealth} → {e.NewHealth}");
};
```

## 线程安全的事件触发

```csharp
// 标准线程安全模式：先拷贝再检查
public event EventHandler OnSomething;

protected virtual void RaiseOnSomething()
{
    // 将事件引用拷贝到局部变量，防止触发前被其他线程取消订阅
    EventHandler handler = OnSomething;
    handler?.Invoke(this, EventArgs.Empty);
}

// C# 6+ 简化写法（编译器内部也是先拷贝的）
// OnSomething?.Invoke(this, EventArgs.Empty);
```

## 事件与委托的关键区别

| | 委托（delegate） | 事件（event） |
|---|---|---|
| 外部赋值 | ✅ 可以 `=` 直接赋值 | ❌ 只能 `+=` / `-=` |
| 外部调用 | ✅ 可以直接调用 | ❌ 只能在声明类内部触发 |
| 清空 | ✅ 可以设为 null | ❌ 外部不能清空 |
| 适用场景 | 回调、策略模式 | 发布-订阅、通知 |

> **为什么需要 event？** 事件的核心价值是**封装**：它限制了外部对委托的操作，防止订阅者被意外清空或从外部触发。

## 常见陷阱

1. **忘记取消订阅 → 内存泄漏**：长生命周期的对象订阅短生命周期对象的事件，会阻止短生命周期对象被 GC 回收。务必在适当时机 `-=`。
2. **事件触发方已销毁**：Unity 中 GameObject 销毁后，其注册的事件回调可能仍在被调用。使用 `?.Invoke` 或 OnDestroy 中取消订阅。
3. **`async void` 事件处理器**：事件处理器如果标记为 `async void`，异常不能被调用方捕获。尽量用 `async Task` + 同步等待，或确保 `try-catch` 包裹整个 `async void` 方法体。

## Unity 中的事件 vs UnityEvent

```csharp
// C# 原生事件 —— 代码侧使用，性能好
public event Action<int> OnScoreChanged;

// UnityEvent —— 可在 Inspector 中可视化配置
using UnityEngine.Events;
public UnityEvent<int> OnScoreChangedUnity;
```

- **C# event**：纯代码，高性能，适合逻辑层
- **UnityEvent**：Inspector 可拖拽配置，适合策划/设计师使用的模块

---

> **总结**：事件 = 对委托的封装，实现发布-订阅模式。核心流程是：声明委托 → 声明事件 → 订阅（`+=`）→ 触发（`?.Invoke`）→ 取消订阅（`-=`）。标准 .NET 事件推荐使用 `EventHandler<TEventArgs>` 模式。
