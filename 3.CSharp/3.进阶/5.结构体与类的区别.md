# 结构体与类的区别

类和结构在设计和使用时有不同的考虑：类适合表示复杂的对象和行为，支持继承和多态性；结构适合表示轻量级数据和值类型，以提高性能并避免引用管理开销。

---

## 核心区别一览

| | 结构（struct） | 类（class） |
|---|---|---|
| 类型 | 值类型 | 引用类型 |
| 内存分配 | 栈（局部变量）/ 堆（类字段中） | 堆 |
| 继承 | ❌ 不能继承（但可实现接口） | ✅ 支持单继承 |
| 默认构造 | ❌ 不能自定义无参构造（C# 10+ 已放开） | ✅ 可自定义 |
| 赋值行为 | **整体复制** | **复制引用** |
| 传参行为 | 传副本（方法内修改不影响原值） | 传引用（方法内修改影响原对象） |
| 可空性 | 需 `Nullable<T>` / `T?` | 默认可为 null |
| 适用场景 | 小而不可变的数据（如 Point, Vector3） | 复杂对象、需要继承多态的实体 |

## 行为对比示例（关键！）

```csharp
// ===== 定义 =====
public struct PointStruct
{
    public int X;
    public int Y;
}

public class PointClass
{
    public int X;
    public int Y;
}

// ===== 测试 =====
void Main()
{
    // 1. 赋值行为对比
    var s1 = new PointStruct { X = 1, Y = 2 };
    var s2 = s1;                    // struct：整体复制
    s2.X = 100;
    Console.WriteLine(s1.X);        // 输出 1（s1 未受影响！）

    var c1 = new PointClass { X = 1, Y = 2 };
    var c2 = c1;                    // class：复制引用
    c2.X = 100;
    Console.WriteLine(c1.X);        // 输出 100（c1 也被改了！）

    // 2. 传参行为对比
    void ModifyStruct(PointStruct p) { p.X = 999; }
    void ModifyClass(PointClass p) { p.X = 999; }

    var s3 = new PointStruct { X = 5 };
    ModifyStruct(s3);
    Console.WriteLine(s3.X);        // 输出 5（不受影响——传的是副本）

    var c3 = new PointClass { X = 5 };
    ModifyClass(c3);
    Console.WriteLine(c3.X);        // 输出 999（被修改了——传的是引用）
}
```

> **这就是 struct 和 class 最关键的行为差异**：struct 赋值/传参是**值的复制**，class 赋值/传参是**引用的复制**。这个差异直接影响你写出的代码行为！

## 装箱（Boxing）—— struct 的隐藏成本

当 struct 被转换为 `object` 或接口类型时，会发生**装箱**：CLR 会在堆上分配内存，复制 struct 数据，并返回一个引用。

```csharp
var point = new PointStruct { X = 1, Y = 2 };

object obj = point;             // ⚠️ 装箱！堆上分配了新对象
var point2 = (PointStruct)obj;  // 拆箱

// 常见装箱场景
IEquatable<PointStruct> eq = point;  // struct 实现接口 → 装箱
string s = $"{point}";               // 调用 value.ToString() → 装箱（除非重写了）
```

**优化建议**：
- 使用泛型避免装箱（`List<T>` 而非 `ArrayList`）
- struct 重写 `ToString()`、`GetHashCode()`、`Equals()` 以避免装箱
- C# 7.2+ 使用 `readonly struct` + `in` 参数减少防御性拷贝

## 现代 C# 中的结构体增强

```csharp
// readonly struct：保证不可变，避免防御性拷贝（C# 7.2+）
public readonly struct Point
{
    public int X { get; }
    public int Y { get; }
    public Point(int x, int y) => (X, Y) = (x, y);
}

// ref struct：强制分配在栈上，不能装箱（典型代表：Span<T>）
public ref struct SpanWrapper
{
    private Span<int> _data;
}

// record struct：值类型的 record（C# 10+）
public readonly record struct Point3D(int X, int Y, int Z);
```

## 何时用 struct？何时用 class？

**用 struct（值类型）**：
- 数据量小（建议 ≤ 16 字节）
- 逻辑上代表一个"值"（如坐标、颜色、复数）
- 不可变或很少修改
- 需要大量创建且生命周期短
- 不需要继承

**用 class（引用类型）**：
- 数据量大
- 需要继承和多态
- 逻辑上代表一个"实体"（如角色、订单、连接）
- 需要共享状态（多个引用指向同一对象）
- 需要为 null 表示"不存在"的状态

> **Unity 中的典型例子**：`Vector3`、`Quaternion`、`Color` 都是 struct，因为它们小而轻量，且语义上是"值"。而 `GameObject`、`Transform`、`MonoBehaviour` 是 class，因为它们需要引用语义和继承。

## 面试常问

> **Q: struct 一定分配在栈上吗？**
> 不一定。局部变量的 struct 在栈上；但作为 class 字段的 struct 在堆上（随 class 对象一起分配）；被装箱的 struct 在堆上。

> **Q: struct 能实现接口吗？**
> 可以，但通过接口调用 struct 的方法会导致装箱。建议配合泛型约束避免装箱。
